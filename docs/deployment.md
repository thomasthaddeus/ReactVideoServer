# Deployment

The current application is optimized for local development, but it should eventually have a clear production shape.

## Recommended Production Model

Use the Express server as the production entry point:

1. Build the client.
2. Serve the built client assets from Express.
3. Keep API routes on the same origin as the client.
4. Store videos, thumbnails, and docs under server-controlled folders.

This avoids cross-origin complexity in production and lets the client use relative API URLs.

## Build

From the repository root:

```powershell
npm run build
```

The client build output is generated by Vite.

## Runtime Configuration

The server needs:

```text
PORT=3001
VIDEO_BASE_PATH=media/videos
THUMBNAIL_BASE_PATH=media/thumbnails
DOCS_BASE_PATH=media/docs
```

For production, choose durable storage paths for videos, thumbnails, and documents. The media folders may be mounted volumes rather than files committed to the repository.

## Client API URL

In development, the client uses `VITE_SERVER_BASE_URL`.

For production, prefer relative URLs if the server serves the built client and API routes from the same origin. That removes the need for production CORS configuration.

## Catalog Generation

Generate the catalog before deployment:

```powershell
npm run generate:catalog
```

Confirm `server/src/data/catalog.json` matches the media files available in the production media folders.

## CI/CD Expectations

A deployment pipeline should:

- Install root, client, and server dependencies.
- Generate or validate the catalog.
- Build the client.
- Run client tests.
- Run server tests.
- Package the server, built client, catalog, and runtime configuration.

## Open Deployment Decision

The app does not yet serve the Vite build from Express. Add that before treating this as production-ready.
